# VDP 仕様書 (アプリケーション開発者向け)

Tang Nano 20K の VDP を、ホスト (RP2350 など) のプログラムから使うための仕様。[rs-kessel](https://github.com/fpt/rs-kessel) の VDP バックエンドなど、
コマンド列を作る側が参照することを想定している。設計の経緯は [ARCHITECTURE.md](ARCHITECTURE.md)、Kessel との対応は [KESSEL_ON_VDP.md](KESSEL_ON_VDP.md)。

この文書は K2 (セルの並び順 2 とスプライトごとのバンク) までの RTL に合わせてある。正確な定義は RTL の先頭のコメント
([`gpu.sv`](../rtl/vdp/gpu.sv)、[`line_compositor.sv`](../rtl/vdp/line_compositor.sv)、[`tile_layer.sv`](../rtl/vdp/tile_layer.sv)、
[`sprite_layer.sv`](../rtl/vdp/sprite_layer.sv)、[`vdp_regs.sv`](../rtl/vdp/vdp_regs.sv)) と、参照モデル [`gpu_model.py`](../tools/harness/gpu_model.py)。
食い違いがあれば RTL が正しい。参照モデルは RTL と同じ画をピクセル単位で作る (CRC が一致する) ので、ホスト側のテストの期待値に使える。

## 1. 概要

- 論理画面は **320 x 240**。出力は縦横 2 倍の 640 x 480 @ 60Hz (HDMI / DVI)
- レイヤ: 背景色、**ビットマップ** (SDRAM のフレームバッファ 2 枚、RGB565 か 8bpp)、**タイルの面 A / B** とウィンドウ、**スプライト** 128 個
- ホストはレイヤのレジスタを書き、VRAM・パレット・OAM を書き、フレームバッファに**コマンドで描く**。VDP がピクセルを直接受け取ることはない
- 合成はライン単位。レジスタは**ラインの合成を始めるときに取り込む**ので、`WAIT_LINE` のあとのレジスタの変更はそのラインから効く (ラスター効果)

```text
ホスト ──SPI──► レジスタ ──► コマンド FIFO (512 ワード) ──► GPU ──► SDRAM (フレームバッファ・アセット)
                                                        │
                                                        ├──► VRAM (64KiB) / パレット (512 色) / OAM (128 個)
                                                        └──► 合成のレジスタ ──► ライン合成 ──► 640x480 出力
```

| 資源 | 大きさ | 書き方 |
| --- | --- | --- |
| SDRAM | 8MiB (2M ワード x 32bit) | `UPLOAD`、描くコマンド |
| VRAM | 16K ワード x 32bit (64KiB) | `VRAM_WRITE` |
| パレット | 512 エントリ x RGB565 | `PAL_WRITE` |
| OAM | 128 エントリ x 2 ワード | `OAM_WRITE` |

ホストから SDRAM・VRAM・パレット・OAM を読み返す方法はない (SDRAM の 1 ワード読み出しはテスト用のレジスタにあるが、アプリケーションでは使わない)。

## 2. ホストとの接続 (SPI)

今のリンクは SPI。本番では HSTX (片方向の 4 ビット DDR) を足す予定で、そのときもコマンドの形式は同じ ([HARNESS2.md](HARNESS2.md))。

| 項目 | 値 |
| --- | --- |
| モード | mode 0 (CPOL 0, CPHA 0)、MSB first、8bit |
| CS | **正論理** (High で選択) |
| クロック | 8MHz まで実機で確認。FPGA が 63MHz でサンプリングするので上限は 10MHz 程度 |
| 電圧 | 3.3V |

配線は [WIRING.md](WIRING.md) (v1) と [HARNESS2.md](HARNESS2.md) (v2)。

### トランザクション

```text
書き込み: CS↑ [0 | addr(7)] [data] [data] ... CS↓     2 バイト目以降は addr, addr+1, ... へ
読み出し: CS↑ [1 | addr(7)] [xx]   [xx]   ... CS↓     2 バイト目以降に addr, addr+1, ... の値が返る
```

- **`0x30`〜`0x3F` はアドレスが進まない** (ポート)。`0x30` (`CMD`) には 1 回のトランザクションで何バイトでも続けて書ける
- 1 バイト目のあいだ、CIPO には同期確認用の `0xA5` が出る
- CS がバイトの途中で下がると `STATUS` のエラーが立つ (そのバイトは捨てられる)

### ほかの線

| 線 | 向き | 意味 |
| --- | --- | --- |
| IRQ | VDP → ホスト | 既定は VBLANK (`CONTROL` bit2 で有効)。`CONTROL` bit4 で **READY** (コマンド FIFO が半分以上空いている) に切り替わる。FPGA が未コンフィグのときは High に見える |
| VSYNC | VDP → ホスト | 垂直同期 (正論理、パルス中 High)。60Hz |
| HEARTBEAT | VDP → ホスト | フレームごとにトグル (30Hz)。リセット中は止まる。「FPGA が動いている」の判定に使う |
| RESET | ホスト → VDP | High でリセット (正論理)。全レジスタが既定に戻る。SDRAM・VRAM・パレット・OAM の中身は保証しない |

**IRQ / READY を信じる前に HEARTBEAT のトグル (か `ID` = `0x5A`) を確かめる** (未コンフィグ時やビットストリームの書き込み中も High なので)。

## 3. レジスタ

複数バイトの値はリトルエンディアン。

### システム (`vdp_regs`)

| アドレス | 名前 | R/W | 内容 |
| --- | --- | --- | --- |
| `0x00` | `STATUS` | R | bit0: VBLANK 中、bit1: エラー (SPI のフレームエラーなど。読むとクリア) |
| `0x01` | `CONTROL` | RW | bit2: IRQ 許可 (IRQ = VBLANK)、**bit3: 合成した画面を表示 (0 ならテストパターン)**、bit4: IRQ ピンを READY にする。bit0, bit1 は予約 (0 を書く)。既定 0 |
| `0x02` | `MARK_COUNT` | R | `MARK_CRC` を更新するたびに 1 増える |
| `0x04` | `FRAME_COUNT` | R | フレームカウンタの下位 8bit |
| `0x05`〜`0x08` | `FRAME_CRC` | R | 直前のフレームの表示の CRC-32 (11 章)。`0x05` を読んだ時点の値を取っておくので、`0x05` から 4 バイト続けて読む |
| `0x09` | `UNDERFLOW` | R | 合成が表示に間に合わなかったライン数 (飽和) |
| `0x0A`〜`0x0B` | `CRC_FRAME` | R | `FRAME_CRC` がリセットから何フレーム目の値か |
| `0x0C`〜`0x0F` | `MARK_CRC` | R | 印を付けたフレーム (`WAIT_VBLANK` の印) の CRC-32 |
| `0x7D` | `SCRATCH` | RW | 書いた値がそのまま読める (リンクの確認用) |
| `0x7E` | `ID` | R | `0x5A` |
| `0x7F` | `VERSION` | R | RTL の版 |

**起動したら `CONTROL` に `0x08` (READY を使うなら `0x18`) を書く。** 既定 (0) ではテストパターンが出ている。

`0x10`〜`0x2F` は SDRAM のテスト用 (アプリケーションでは触らない)。

### GPU (`gpu`)

| アドレス | 名前 | R/W | 内容 |
| --- | --- | --- | --- |
| `0x30` | `CMD` | W | コマンドのポート。書いたバイトを 4 つずつ (リトルエンディアン) 1 ワードにして FIFO に入れる |
| `0x40` | `GPU_STATUS` | R | bit0: 実行中 (FIFO にワードがある / コマンドを実行している)、bit1: エラー (知らないコマンドなど。読むとクリア)、bit2: FIFO があふれた (読むとクリア) |
| | | W | bit0 に 1: FIFO とワードの組み立てを空にする (実行中のコマンドはそのまま) |
| `0x41`〜`0x42` | `GPU_FREE` | R | FIFO の空き (ワード数)。ホストはこの数 x 4 バイトまで送ってよい |
| `0x44`〜`0x45` | `FB_BASE` | RW | 表示する面の先頭 (1KiB 単位、13bit)。既定 0 |
| `0x46`〜`0x47` | `DRAW_BASE` | RW | 描く面の先頭 (同じ単位)。既定 256 (= バイト `0x040000`) |
| `0x48`〜`0x49` | `BG_COLOR` | RW | 背景色 (RGB565) |
| `0x4A` | `LAYER_CTRL` | RW | 5 章と同じ |
| `0x4C`〜`0x4D` | `BITMAP_KEY` | RW | 5 章と同じ |

`BG_COLOR` `LAYER_CTRL` `BITMAP_KEY` はホストから直接も書けるが、ラインに合わせたいときはコマンドの `REG_WRITE` を使う (FIFO の順に効く)。

### 流量の制御

FIFO は 512 ワード。あふれたワードは捨てられ、`GPU_STATUS` bit2 が立つ。どちらかで制御する:

- **READY の線** (`CONTROL` bit4): High のあいだは 256 ワードまで送ってよい (High = 空きが半分以上)
- **`GPU_FREE` を読む**: 読んだ空き x 4 バイトまで送る

`WAIT_LINE` / `WAIT_VBLANK` / `SWAP` で GPU が待っているあいだも FIFO には積める。1 フレーム分 (目安 512 ワード以下) を先に送っておくと、
`WAIT_LINE` のあとの `REG_WRITE` が遅れない (8 章)。

## 4. コマンド

コマンドは 32bit ワードの列。先頭ワードの `[31:24]` がコマンド番号、引数のワードが続く。座標の組は `{y[15:0], x[15:0]}` (下位が x)。
FIFO の順に 1 つずつ実行する (描くコマンドも `WAIT_LINE` も同じ列に並ぶ)。

| 番号 | コマンド | ワード数 | 概要 |
| --- | --- | --- | --- |
| `0x00` | `NOP` | 1 | 何もしない |
| `0x01` | `CLEAR` | 1 | 描く面の全体を塗る |
| `0x02` | `FILL_RECT` | 3 | 矩形を塗る |
| `0x03` | `SWAP` | 1 | 表示する面と描く面を入れ替える |
| `0x04` | `UPLOAD` | 2 + n | SDRAM に n ワード書く |
| `0x05` | `POINT` | 2 | 1 ピクセル |
| `0x06` | `DRAW_LINE` | 3 | 線 |
| `0x07` | `CLIP` | 3 | クリップ矩形 |
| `0x08` | `BLIT` | 5 | SDRAM の画像を描く面に写す (8bpp では 4bpp のソースも) |
| `0x09` | `REG_WRITE` | 1 | 合成のレジスタ (5 章) |
| `0x0A` | `WAIT_LINE` | 1 | ライン n まで待つ |
| `0x0B` | `WAIT_VBLANK` | 1 | 次のフレームのライン 0 まで待つ (印を付けられる) |
| `0x0C` | `VRAM_WRITE` | 2 + n | VRAM に n ワード |
| `0x0D` | `PAL_WRITE` | 2 + ⌈n/2⌉ | パレットに n 色 |
| `0x0E` | (予約) | — | `STRETCH_BLIT` に取ってある。今はエラー |
| `0x0F` | `OAM_WRITE` | 2 + n | OAM に n ワード |
| ほか | — | 1 | エラーを立て、1 ワードのコマンドとして読み飛ばす |

### 色

描くコマンドの色は、面の形式 (`BITMAP_FMT`、5 章) で意味が変わる。

- **RGB565** (`BITMAP_FMT` = 0): `[15:0]` が RGB565 の色
- **8bpp** (`BITMAP_FMT` = 1): `[7:0]` がパレットの番号 (0..255)。`[15:8]` は無視 (`BLIT` の 4bpp では `[11:8]` がバンク)

`BITMAP_FMT` は描くコマンドには**すぐ**効く。面の中身の形式を覚えているわけではないので、描くときと表示するときの形式をホストが揃える。

### 各コマンド

**`CLEAR`** `[0x01, -, color]`
描く面の 320 x 240 全体を塗る。**クリップ矩形は効かない。**

**`FILL_RECT`** `[0x02, -, color]` `{y, x}` `{h, w}`
x, y, w, h は**符号なし**。画面の外にはみ出した部分とクリップ矩形の外は描かない。w = 0 か h = 0 なら何もしない。
画面の外 (負の座標) から始まる矩形は、ホストが切ってから送る。

**`SWAP`** `[0x03]`
`FB_BASE` と `DRAW_BASE` を入れ替える。表示側が新しい `FB_BASE` を取り込む (次のフレームのライン 0 の合成を始める) まで、**後続のコマンドを待たせる**。
なので `SWAP` のあとのコマンドは、前の表示面 (= 新しい描く面) を安全に描ける。

**`UPLOAD`** `[0x04, n(24bit)]` `addr` `data × n`
SDRAM のワードアドレス `addr` (21bit) から n ワード書く。1 ワードずつ書くので速くない (8 章)。アセットは起動時にまとめて送る。

**`POINT`** `[0x05, -, color]` `{y, x}`
x, y は**符号付き** 16bit。クリップ矩形の中なら 1 ピクセル描く。

**`DRAW_LINE`** `[0x06, -, color]` `{y0, x0}` `{y1, x1}`
符号付き。ブレゼンハムで両端を含めて描く。画面の外から始まる線もよい (クリップ矩形の外のピクセルは飛ばす)。
傾きの規則は `err = dx + dy` (dy は負)、`e2 = 2 err`、`e2 >= dy` で x、`e2 <= dx` で y を進める (参照モデルの `bresenham()`)。

**`CLIP`** `[0x07]` `{y0, x0}` `{y1, x1}`
符号なし、両端を含む。以降の `FILL_RECT` `POINT` `DRAW_LINE` `BLIT` をこの矩形の中だけにする。画面の外は画面の端に丸める。
x0 > x1 などなら何も描かなくなる。既定は画面全体 (`0,0`〜`319,239`)。

**`BLIT`** `[0x08, flags(8), key(16)]` `src` `{h, w}` `{y, x}` `stride`
SDRAM のワードアドレス `src` にある w x h の画像を、描く面の (x, y) (符号付き) に写す。`stride` はソースの 1 行のワード数 (下位 16bit)。

| flags | 意味 |
| --- | --- |
| bit0 | 透過: 透過色 (下) のピクセルを書かない |
| bit1 | 左右反転 |
| bit2 | 上下反転 |
| bit3 | 4bpp のソース (BLIT4)。**8bpp のときだけ**。RGB565 で立てるとエラーになり何も描かない |

| 面の形式 | ソース | 1 ワードのピクセル | 書く値 | 透過色 |
| --- | --- | --- | --- | --- |
| RGB565 | RGB565 | 2 (下位 16bit が左) | そのまま | `key` (RGB565) |
| 8bpp | 8bpp | 4 (バイト i がピクセル i) | そのまま | `key[7:0]` |
| 8bpp | 4bpp (bit3) | 8 (ピクセル i は `[31-4i -: 4]`) | `{key[11:8], ピクセル}` | 値 0 |

- ソースの各行は**ワードの先頭から始まる** (行の途中のピクセルから切り出すときは、`src` をワード単位で、左端をワードの境目に揃える)
- w は 512 まで (越えるとエラー)。h は 240 を越えてもよい (はみ出しは描かない)
- 4bpp のソースはタイルの 1 行と同じ並び。タイルのシート (6 章) を SDRAM に `UPLOAD` すれば、タイル t は `src = base + 8t`、`stride = 1`、`w = h = 8`
- ソースは SDRAM だけ。VRAM・描く面と重なるソースの動きは決めていない (重ねない)
- クリップ矩形と画面の外は描かない

**`REG_WRITE`** `[0x09, reg(8), value(16)]`
合成のレジスタ `reg` に値を書く (5 章)。知らない番号はエラー。

**`WAIT_LINE`** `[0x0A, -, n(8)]`
以降のコマンドを、ライン n の合成が始まる直前 (ライン n-1 の合成が始まったところ) まで待たせる。
**これより後の `REG_WRITE` はライン n から効く。** n = 0 は `WAIT_VBLANK` と同じ。n は 0..239。
すでにライン n を過ぎていたら、次のフレームのライン n まで待つ。

**`WAIT_VBLANK`** `[0x0B, -, mark(1)]`
`WAIT_LINE 0` と同じ: ライン 239 の合成が始まった直後まで待つ (以降の `REG_WRITE` は次のフレームのライン 0 から効く)。
そこからライン 0 の合成までは約 1.5ms (8 章)。
`[0]` = 1 なら次のフレームに印を付け、その CRC を `MARK_CRC` に残す (11 章)。

**`VRAM_WRITE`** `[0x0C, n(24)]` `addr` `data × n`
VRAM のワードアドレス `addr` から n ワード (16K ワードで折り返す)。1 クロック 1 ワード。

**`PAL_WRITE`** `[0x0D, n(24)]` `index` `data × ⌈n/2⌉`
パレットの `index` (0..511) から n 色。1 ワードに 2 色 (下位 16bit が先)。n が奇数なら最後のワードの上位は使わない。512 で折り返す。

**`OAM_WRITE`** `[0x0F, n(24)]` `addr` `data × n`
OAM のワードアドレス `addr` (エントリ k はワード 2k と 2k+1) から n ワード (256 ワードで折り返す)。形式は 6 章。

VRAM・パレット・OAM の書き込みは**すぐ**効く (ラインに合わせない)。表示中に書くと、そのフレームの途中から変わる (8 章)。

## 5. 合成のレジスタ (`REG_WRITE`)

どれもラインの合成を始めるときに取り込む。値は各レジスタの幅に切る。

| 番号 | 名前 | 幅 | 既定 | 内容 |
| --- | --- | --- | --- | --- |
| 0 | `BG_COLOR` | 16 | 0 | 背景色 (**RGB565**、パレットの番号ではない)。どのレイヤも書かなかったピクセルの色 |
| 1 | `LAYER_CTRL` | 5 | 1 | bit0: ビットマップ、bit1: ビットマップの透過色を有効、bit2: 面 A (とウィンドウ)、bit3: スプライト、bit4: 面 B |
| 2 | `BITMAP_KEY` | 16 | 0 | ビットマップの透過色。RGB565 の面では色、8bpp の面では `[7:0]` がパレットの番号 |
| 3 | `TILE_SCROLL_X` | 10 | 0 | 面 A の横スクロール (ピクセル) |
| 4 | `TILE_SCROLL_Y` | 10 | 0 | 面 A の縦スクロール |
| 5 | `TILE_MAP_BASE` | 14 | 0 | 面 A のマップの VRAM のワードアドレス |
| 6 | `TILE_PAT_BASE` | 14 | 0 | 面 A (とウィンドウ) のタイルの VRAM のワードアドレス |
| 7 | `TILE_CTRL` | 8 | 0 | 面 A の設定 (6 章の「面の設定」) |
| 8 | `BITMAP_RANK` | 3 | 1 | ビットマップの順位 (7 章)。0 なら書かない |
| 9 | `SPR_PAT_BASE` | 14 | 0 | スプライトのタイルの VRAM のワードアドレス |
| 10 | `SPR_BANK` | 4 | 0 | `[2:0]` スプライトのパレットのバンク (64 色単位)。`[3]` = 1 ならスプライトごとのバンク (OAM ワード 1 の `[19:16]`) を使う |
| 11 | `SPR_LINE_PX` | 10 | 320 | 1 ラインのスプライトのピクセル数の上限 (8 の倍数に切り捨て) |
| 12〜16 | `TILEB_SCROLL_X` `TILEB_SCROLL_Y` `TILEB_MAP_BASE` `TILEB_PAT_BASE` `TILEB_CTRL` | | 0 | 面 B (面 A と同じ形) |
| 17 | `WIN_H` | `[7]`, `[4:0]` | 0 | ウィンドウの横: `[7]` = 1 なら右側、位置 = `[4:0]` x 16 ピクセル |
| 18 | `WIN_V` | `[7]`, `[4:0]` | 0 | ウィンドウの縦: `[7]` = 1 なら下側、位置 = `[4:0]` x 8 ライン |
| 19 | `WIN_MAP_BASE` | 14 | 0 | ウィンドウのマップ (64 x 32、スクロールしない) |
| 20 | `HSCROLL_MODE` | 2 | 0 | 横スクロールの表: 0 なし (レジスタ)、1 画面全体、2 8 ラインごと、3 ラインごと |
| 21 | `HSCROLL_BASE` | 14 | 0 | 横スクロールの表の VRAM のワードアドレス |
| 22 | `BITMAP_FMT` | 1 | 0 | ビットマップの形式: 0 = RGB565、1 = 8bpp。描くコマンドにはすぐ、表示には次のラインから |

### ウィンドウ

メガドラと同じ規則。ラインが縦の範囲 (`WIN_V`: 下側なら `line >= 位置`、上側なら `line < 位置`) に入ればライン全体がウィンドウ、
入らなければ横の範囲 (`WIN_H`: 右側なら `x >= 位置`、左側なら `x < 位置`) だけ。ウィンドウの中では面 A を描かず、代わりに
`WIN_MAP_BASE` の 64 x 32 のマップをスクロールなしで描く。タイルの場所・パレットのバンク・エントリの並びは面 A のもの、順位も面 A と同じ。
`WIN_H` = `WIN_V` = 0 ならウィンドウなし。

### 横スクロールの表

`HSCROLL_MODE` が 0 でなければ、ラインごとに VRAM の `HSCROLL_BASE + 番号` の 1 ワードを読み、`[25:16]` を面 A、`[9:0]` を面 B の値にする。
番号はモード 1: 0、2: `line & ~7`、3: `line`。**値の向きはメガドラと同じで、正の値で面が右に動く** (`scroll_x = -値`)。
このとき `TILE_SCROLL_X` / `TILEB_SCROLL_X` は使わない (縦スクロールはレジスタのまま)。

## 6. データ形式

### フレームバッファ (SDRAM)

1 ラインは SDRAM の 1 行 (256 ワード = 1KiB) に置く。面の先頭を `base` (1KiB 単位) とすると、ライン y はワードアドレス `(base + y) * 256` から。

| 形式 | 1 ワードのピクセル | ピクセル x の場所 | 1 ラインのワード数 |
| --- | --- | --- | --- |
| RGB565 | 2 | ワード `x / 2` の `[16 (x % 2) +: 16]` | 160 |
| 8bpp | 4 | ワード `x / 4` の `[8 (x % 4) +: 8]` | 80 |

RGB565 は `{R[4:0], G[5:0], B[4:0]}`。8bit への広げ方は上位ビットの繰り返し (`R8 = {R5, R5[4:2]}` など)。

SDRAM の使い方 (決まりではなく既定の値):

| バイトアドレス | 用途 |
| --- | --- |
| `0x000000` | 面 0 (`FB_BASE` の既定 0) |
| `0x040000` | 面 1 (`DRAW_BASE` の既定 256) |
| `0x080000`〜 | 空き (アセット: BLIT のソース、4bpp のタイルのシートなど) |

ワードアドレスは 21bit (`0`〜`0x1FFFFF`)。面は 240 行 = 240KiB を使う。

### パレット

512 エントリ x RGB565。全レイヤで共有する。

| 使う側 | 番号 |
| --- | --- |
| タイルの面 | `{TILE_CTRL[6:4] (バンク), エントリのパレット (2bit), ピクセルの値 (4bit)}` = バンク x 64 + パレット x 16 + 値 |
| スプライト | `{SPR_BANK[2:0], エントリのパレット (2bit), ピクセルの値}`。`SPR_BANK[3]` = 1 なら `{0, スプライトのバンク (4bit), ピクセルの値}` (0..255、8bpp・BLIT4 と同じ番号) |
| 8bpp のビットマップ | 0..255 (ピクセルの値そのまま) |
| BLIT4 | 描く値 `{バンク (4bit), ピクセル}` が 8bpp の番号になる (0..255) |

### タイル (VRAM)

8 x 8 ピクセル、4bpp。1 行が 1 ワードで、**ピクセル i (左から) は `[31-4i -: 4]`** (上位のニブルが左)。タイル t の行 r はワード `pat_base + 8t + r`。
ピクセルの値 0 は透明。タイル番号は 11bit (0..2047)。VRAM は 16K ワードなので、マップと合わせて 64KiB に収める。

同じ形式のデータを SDRAM に置けば BLIT4 のソースになる (タイル 1 個 = 8 ワード、stride 1)。

### マップのエントリ (面 A / B / ウィンドウ)

16bit、1 ワードに 2 つ。

| ビット | 意味 |
| --- | --- |
| `[10:0]` | タイル番号 |
| `[11]` | 左右反転 |
| `[12]` | 上下反転 |
| `[14:13]` | パレット (0..3) |
| `[15]` | 優先度 (7 章) |

列 c、行 r のエントリは `map_base + (r * 幅 + c) / 2` の、偶数の列なら下位 16bit (面の設定 `[7]` = 1 なら上位 = メガドラの並び)。

### 面の設定 (`TILE_CTRL` / `TILEB_CTRL`)

| ビット | 意味 |
| --- | --- |
| `[1:0]` | マップの幅: 0 = 32、1 = 64、2 = 128 タイル |
| `[3:2]` | 高さ: 0 = 32、1 = 64、2 = 128、3 = 28 タイル (このときは scroll_y < 224) |
| `[6:4]` | パレットのバンク (64 色単位) |
| `[7]` | エントリの並び: 0 = 下位が偶数の列、1 = 上位が偶数の列 (メガドラの VRAM をビッグエンディアンの 32bit で読んだ並び) |

画面のピクセル (x, line) は、マップのピクセル `((x + scroll_x) mod 幅, (line + scroll_y) mod 高さ)`。**面は折り返して画面全体を覆う**。

### OAM (スプライト)

128 エントリ、エントリ n はワード 2n (ワード 0) と 2n+1 (ワード 1)。

| ワード | ビット | 意味 |
| --- | --- | --- |
| 0 | `[9:0]` | x (符号付き 10bit、画面の左端が 0) |
| 0 | `[25:16]` | y (符号付き 10bit) |
| 0 | `[27:26]` | 幅 - 1 (タイル、1〜4) |
| 0 | `[29:28]` | 高さ - 1 (タイル、1〜4) |
| 0 | `{[10], [30]}` | セルの並び順 (下) |
| 0 | `[31]` | 有効 |
| 1 | `[15:0]` | マップのエントリと同じ形 (先頭のタイル、左右反転、上下反転、パレット、優先度) |
| 1 | `[19:16]` | スプライトごとのバンク (`SPR_BANK[3]` = 1 のときだけ使う。そのときエントリのパレット `[14:13]` は使わない) |

ほかのビット (ワード 0 の `[15:11]`、ワード 1 の `[31:20]`) は 0 にする (将来使う)。

セルの並び順 (スプライトの中の列 c、行 r のタイル):

- 0: 列優先 (メガドラ) — `先頭 + c * 高さ + r`
- 1: 16 タイル幅の表 (SNES) — `{先頭[10:4] + r, 先頭[3:0] + c}` (列は表の行の中で折り返す)
- 2: 行優先、ストライドはスプライトの幅 (Kessel の `sprn`) — `先頭 + r * 幅 + c`
- 3: 予約 (今は 2 と同じ。使わない)

左右反転はタイルの列の順番とタイルの中のピクセルの両方を、上下反転は行の順番とタイルの中の行の両方を逆にする。

## 7. 合成 (レイヤと順位)

ピクセルごとに、順位の一番高いレイヤの色が出る。どのレイヤも書かなかったところは `BG_COLOR`。

| 順位 | レイヤ |
| --- | --- |
| 0 | 背景色 |
| 1 | 面 B (低優先) |
| 2 | 面 A (低優先) とウィンドウ |
| 3 | スプライト (低優先) |
| 4 | 面 B (高優先) |
| 5 | 面 A (高優先) とウィンドウ |
| 6 | スプライト (高優先) |
| `BITMAP_RANK` | ビットマップ (0〜7) |

- 優先度はタイルのエントリ / OAM の `[15]`
- **同じ順位なら、先に書いたほうが残る**。書く順は スプライト → 面 B → 面 A → ウィンドウ → ビットマップ。
  なので `BITMAP_RANK` = 6 は、すべての面より上で、高優先のスプライトより下 (低優先のスプライトよりは上) になる
- スプライト同士は優先度によらず **OAM の前のエントリが勝つ** (メガドラ・SNES と同じ)
- タイル・スプライトのピクセルの値 0 は透明。ビットマップは `LAYER_CTRL` bit1 が立っているとき、透過色 (`BITMAP_KEY`) のピクセルが透明

よく使う組み合わせ:

| 狙い | 設定 |
| --- | --- |
| 面の上に即時描画、その上にハードスプライト (Kessel の 3 段) | `BITMAP_RANK` = 6、透過あり、スプライトは高優先 |
| ビットマップを一番上 (HUD) | `BITMAP_RANK` = 7 |
| ビットマップを一番下 (背景画) | `BITMAP_RANK` = 1 (既定)、面は透明なところから下が見える |

## 8. タイミング

### 映像

| 項目 | 値 |
| --- | --- |
| 出力 | 640 x 480 @ 60Hz (ピクセルクロック 25.2MHz)、1 フレーム 525 ライン x 800 クロック = 16.67ms |
| 論理ライン | 出力 2 ライン = 63.5us |
| VBLANK | 出力ライン 480〜524 (45 ライン = 1.43ms)。`STATUS` bit0、IRQ |
| GPU・SDRAM のクロック | 63MHz |

### 合成

- 論理ライン n は、ライン n-1 を表示しているあいだ (63.5us = 63MHz で 4,000 クロック) に合成する。ライン 0 は VBLANK の最後から 2 本目の出力ラインで合成する
- レジスタは合成を始めるときに取り込む。`WAIT_LINE n` が終わるのはライン n-1 の合成が始まった直後なので、そのあと FIFO にある `REG_WRITE` は数クロックで実行され、ライン n に間に合う
- **FIFO が空で、`WAIT_LINE` のあとの `REG_WRITE` がまだ届いていないと、効くラインがずれる**。ラスター効果を使うフレームは、そのフレームのコマンドを先に送っておく
- 1 ラインの合成の重さ (63MHz のクロック数、締め切り 4,000): スプライトの OAM の走査 約 130 + 描くスプライトの列ごとに約 10、面 1 枚 約 450、
  RGB565 のビットマップ 約 170、8bpp のビットマップ 約 410。今あるシナリオの最悪は 2,057 (面 2 枚 + スプライトの上限 1023 ピクセル)。
  間に合わなかったラインは `UNDERFLOW` に数える

### 描くコマンドの速さ (目安)

GPU は 63MHz。書き込みは 1 行の中で 64 ワードずつのバースト。表示の読み出しが優先なので、多少待たされる。

| コマンド | 目安 |
| --- | --- |
| `CLEAR` (RGB565) | 約 0.7ms (38,400 ワード) |
| `CLEAR` (8bpp) | 約 0.35ms (19,200 ワード) |
| `FILL_RECT` | 1 行あたり 数十クロック + ワード数 |
| `BLIT` | 1 行あたり ソースの読み (数十クロック + ソースのワード数) + 書き (数十クロック + 描くワード数)。8x8 の BLIT4 で 数百クロック |
| `DRAW_LINE` / `POINT` | 1 ピクセル 10 クロック程度 (クリップの外は 2 クロック) |
| `UPLOAD` | 1 ワード 10 クロック程度 |
| `VRAM_WRITE` / `PAL_WRITE` / `OAM_WRITE` | 1 ワード 3 クロック程度 (FIFO から読む速さ) |

リンクの速さ: SPI 8MHz で約 1MB/s = 1 フレーム約 16KiB (4,000 ワード)。1 フレームのコマンドはこれに収める。

### 書き込みと表示の関係

- フレームバッファ: 描く面 (`DRAW_BASE`) に描き、`SWAP` で表示を切り替える (切り替わるのは次のフレームのライン 0)。表示中の面に描くとちらつく
- VRAM・パレット・OAM: すぐ効く。フレームの途中で書き換えるとその場から変わる。表示を乱したくなければ `WAIT_VBLANK` のあとに書く。
  `WAIT_VBLANK` が終わるのはライン 239 の合成が始まった直後 (出力ライン 476) で、そこからライン 0 の合成 (出力ライン 523) までは約 1.5ms (約 90,000 クロック)。
  GPU は 1 ワード 3 クロックで書けるので、量の制限は実際にはリンクの速さ (SPI 8MHz で 1.5ms に約 1.5KiB。先に FIFO に積んでおけば 512 ワードまでは待たずに実行される)
- ただし `WAIT_VBLANK` の直後は、ライン 239 (今のフレームの最後のライン) の合成がまだ数十 µs 続いている。直後の書き込みはそのラインに混ざることがある
  (M9 のデモは `WAIT_VBLANK` の直後に OAM を書いている。影響しうるのは最後の 1 ラインだけ)

## 9. 制限

### 画面・レイヤ

- 論理画面は 320 x 240 固定。回転・拡大縮小・半透明・色の加算はない
- タイルの面は 2 枚 (A / B) + ウィンドウ。縦スクロールは面ごとに 1 つ (列ごとの縦スクロールはない)。ウィンドウは面 A の代わりにだけ出せる
- 面は必ず折り返して画面全体を覆う (マップの一部だけを出すには、使わないところをタイル 0 にする)
- パレットは 512 色。タイル・スプライト・8bpp のビットマップで共有する

### スプライト

- 128 個。大きさは 1〜4 x 1〜4 タイル (8〜32 ピクセル)
- 1 ラインの上限は `SPR_LINE_PX` / 8 列 (タイルの列の数)。**画面の外の列も数える** (メガドラと同じ)。上限を越えたスプライトの残りの列と、後ろのエントリは描かない。
  設定できるのは 1023 ピクセル (127 列) まで。どの値でも、面 2 枚とビットマップを合わせて合成は締め切りに間に合う
- `SPR_BANK[3]` = 0 のとき、1 つのスプライトが使えるパレットは `SPR_BANK` の 64 色 (4 パレット) だけ。`SPR_BANK[3]` = 1 なら
  スプライトごとに 16 色のバンク 16 個 (パレット 0..255) から選べる。どちらのモードかは全スプライト共通 (ラインごとには切り替えられる)

### ビットマップと描くコマンド

- `FILL_RECT` の座標は符号なし (負の座標は使えない。ホストが切る)。`POINT` `DRAW_LINE` `BLIT` は符号付き
- `CLEAR` はクリップ矩形を無視する
- `BLIT` の幅は 512 ピクセルまで。ソースは SDRAM だけで、各行はワードの境目から始まる。拡大縮小 (`STRETCH_BLIT`) はまだない
- 4bpp のソース (BLIT4) は 8bpp の面にだけ描ける
- 塗りつぶしの三角形・円はない (線と矩形で組む)
- 描く面の形式は `BITMAP_FMT` の今の値で決まる。面が RGB565 か 8bpp かは VDP は覚えていない

### リンク

- コマンドの流れは片方向。結果 (描き終わったか) は `GPU_STATUS` bit0 か FIFO の空きで知る
- ホストから SDRAM・VRAM・パレット・OAM は読めない

## 10. 1 フレームの組み立て方

```text
起動:
  CONTROL = 0x18                       合成した画面を表示、IRQ ピンを READY に
  UPLOAD / VRAM_WRITE / PAL_WRITE      アセット (BLIT のソース、タイル、マップ、パレット)
  REG_WRITE                            面・スプライトの設定、BITMAP_FMT など

毎フレーム:
  WAIT_VBLANK                          ここからは次のフレームのライン 0 の前
  REG_WRITE (ライン 0 の値)              スクロール、背景色など
  OAM_WRITE / VRAM_WRITE (マップの差分)  VBLANK のあいだに
  SWAP                                 前のフレームで描いた面を表示に (次のフレームのライン 0 から)。
                                       表示が取り込むまで後続は待つので、ここから描く面は空いている
  [WAIT_LINE n + REG_WRITE ...]         ラスター効果 (使うなら)
  CLEAR / FILL_RECT / DRAW_LINE / BLIT  次のフレームの画を描く面に
```

- ラスター効果 (`WAIT_LINE`) と描くコマンドは同じ列に並ぶ。`WAIT_LINE` で待つあいだは描画も止まるので、
  描くコマンドは最後の `WAIT_LINE` のあとか、`WAIT_LINE` のあいだに収まる量を置く ([`demo.py`](../tools/harness/demo.py) の並べ方が例)
- 1 フレームのコマンドは FIFO (512 ワード) と READY で流す。READY が落ちたら待つ
- 8bpp で、面 (タイル) と即時描画を重ねるフレームは、`CLEAR` を透過色で行い `LAYER_CTRL` bit1 を立てる。重ねないフレームは透過を切り、
  `CLEAR` を普通の色で (KESSEL_ON_VDP.md の 2 章)

## 11. 検証の手がかり

- **`FRAME_CRC`**: 直前のフレームの表示 (640 x 480 の DE 中のピクセルを R, G, B の順のバイト列にしたもの) の CRC-32。
  Python の `zlib.crc32` と同じ (IEEE 802.3)。論理画面 320 x 240 の RGB565 の画からは
  `fbmodel.expected_crc(img565)` (縦横 2 倍、565 → 888 の広げ方込み) で同じ値が作れる
- **印**: `WAIT_VBLANK` の `[0]` = 1 で次のフレームに印を付けると、そのフレームの CRC が `MARK_CRC` に残り、`MARK_COUNT` が 1 増える。
  ラインごとにレジスタを変えたフレームを比べるのに使う
- **参照モデル**: [`gpu_model.py`](../tools/harness/gpu_model.py) の `Model` にコマンドのワード列を `run()` で渡すと、表示される画 (`displayed565()`)
  と印を付けたフレーム (`marked565()`) を作る。RTL と同じ CRC になる。ホスト側 (Kessel のソフトラスタライザ) との突き合わせに使える
- **シナリオ**: `scenarios/*.json` は、同じコマンド列を参照モデル・Verilator・実機で走らせて CRC を比べるためのもの ([HARNESS.md](HARNESS.md))。
  K1 の機能は `scenarios/k1_8bpp.json`
