# M5 着手前のレビュー

[GPU_PLAN.md](GPU_PLAN.md) の M0〜M4 を読んだ時点で、M5 以降に効きそうな点をまとめたもの。
エミュレータ向けの方向性は [EMU_GPU_PLAN.md](EMU_GPU_PLAN.md) を参照。

## 全体への所感

- 参照モデル / Verilator / 実機の 3 通り突き合わせ、CRC で合否を決めてキャプチャは目視代わり、という切り分けは、AI に自律で回させる土台としてよくできている
- SDRAM の取り込み位置の件 (1 ワード読みでは 6,7 も通ったが、バーストでは 5 だけ) は、バースト化する前に気づけていてよい教訓

## 1. SDRAM の取り込み位置が「5 だけ」なのは余裕がない

- 半周期刻みで 1 点しか通らないと、温度・電圧・配置配線が変わったときに落ちる可能性がある
- M5 でロジックが増えて配置が変わった瞬間に CRC が揺れ出す、というのが起こりそう
- 対策
  - 計画にある PSDA (位相調整) を早めにやって、「4〜6 が通る」程度の中心に据える
  - 少なくとも BIST を CI の毎回の実機テストに入れ、取り込み位置の掃引結果を毎回記録する
  - ボードを移行したとき (16bit 幅 SDRAM など) は掃引をやり直す

## 2. RGB565 を 2 ピクセル / ワードで詰めると、FILL_RECT・BLIT の端で問題になる

- x が奇数で始まる・終わる矩形は、ワードの片側だけ書く必要がある
- 読み‐修正‐書き (RMW) にすると帯域とアービタの複雑さが倍になる
- 対策: SDRAM の DQM (バイトマスク) で片ピクセルだけ書く方式を先に決めておく
  - BLIT の透過色も同じで、DQM を使えばピクセル単位の書き飛ばしが RMW なしでできる
  - `sdram_ctrl` のバースト書きに DQM 入力を足すのを M5 のスコープに入れると、M7 (BLIT) が楽になる
- 備考: 16bit 幅 SDRAM のボードに移ると 1 ワード 1 ピクセルになり、この問題は消える。データ幅をパラメータにしておく

## 3. SWAP の意味を決めておく

- 「次の VBLANK で切り替え、終わるまで後続を待たせる」で良い
- ただし、描画中のフレームと表示中のフレームの base を scanout 側がどのタイミングでラッチするか (フレーム先頭のライン 0 先読み開始時か、VBLANK 開始時か) で、参照モデルと 1 フレームずれやすい
- 対策: 参照モデルで「どのフレームの CRC か」を明示的に扱えるようにしておく。M8 の「毎フレームの CRC 一致」で詰まりにくくなる

## 4. 帯域は十分だがアービタの粒度に注意

- 表示の 1 ライン読み出しは ACT + 160 READ + PRE で、63MHz なら約 2.7µs。水平周期は約 31.8µs なので余裕はある
- ただし描画側のバーストが長い (例: CLEAR の 1 行 160 ワード書き) と、表示要求が来たときに待たされる
- 対策 (どちらか)
  - 描画側のバースト長に上限 (32〜64 ワード程度) を付ける
  - 表示要求で描画バーストを中断できるようにする
- どちらにしても、最悪ケースを Verilator で数えて UNDERFLOW が出ないことをテストにする

## 5. アップロードの 4.8 秒

- M5 の UPLOAD で一括送信にする予定とのこと
- RP2 側の `spi` が 1 回 4KiB までなので、640 バイト/ライン → 4KiB なら 6 ライン、240 ライン で 40 往復程度には減る
- RP2 を固定する方針なので、FPGA 側の FIFO 深さと SPI 側のフロー制御 (STATUS の FIFO 残量をホストが見る) が UPLOAD と CMD で共通化できると、ホストのコードも単純になる
- 備考: 本番のホストリンク (HSTX など) では READY の GPIO 1 本でフロー制御する想定なので、FIFO 残量の扱いはそこでも流用できる形にしておく
